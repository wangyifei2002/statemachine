# DSP 瞄捕状态机模拟器技术方案

本项目实现的是一个基于 Web 的 DSP 瞄捕状态机演示系统，目的是把抽象的状态流转过程、模块协同关系以及不同工作阶段下的链路变化直观展示出来，便于用于方案汇报、技术讲解、原理演示和联调说明。系统以 `S0` 到 `S5` 六个状态为核心，通过页面交互驱动状态切换，并同步更新当前状态说明、上行链路模式、架构图高亮效果和运行日志。整体方案采用轻量化实现方式，前端界面和主要逻辑统一由 `Streamlit` 承载，不需要额外搭建复杂前后端架构，适合快速开发、快速部署和快速迭代。

从实现结构上看，系统的核心思路是“配置驱动 + 状态联动 + 双视角可视化”。代码中首先使用常量集中定义状态名称、状态描述、状态转移关系以及上行链路映射关系，其中 `STATE_NAMES`、`STATE_DESCRIPTIONS` 用来统一管理状态展示文案，`STATE_TRANSITIONS` 用来定义当前状态可切换到哪些目标状态，以及每一次切换对应的触发事件和提示说明，`UPLINK_MODE` 则负责定义不同状态下系统采用毫米波还是太赫兹作为上行模式。采用这种方式的好处是业务逻辑和界面行为高度一致，后续如果需要增加新状态、修改状态含义或者调整跳转关系，只需要改动配置数据，不需要改写大量页面逻辑，整体可维护性更高。

在运行机制上，系统依赖 `Streamlit` 的 `st.session_state` 维护当前会话中的核心运行数据，包括当前状态、日志列表和上行链路模式。页面首次打开时会默认初始化为 `S0` 自检状态，同时初始化空日志和对应的毫米波链路模式。用户每次点击按钮触发状态变化后，程序会先读取当前状态，再写入目标状态，根据目标状态同步刷新上行链路模式，随后生成一条带有时间戳的日志记录，并调用 `st.rerun()` 重新渲染页面。由于所有显示区域都基于同一份会话状态进行计算，因此整个页面能够在一次操作后同步更新，保证物理架构图、状态机拓扑图、状态卡片和日志区在语义上保持一致。

从页面组织方式来看，界面分为“顶部总览、中部控制、底部记录”三个主要区域。顶部展示物理架构与数据流向图，这是用户理解系统整体运行方式的第一视角；中部左侧展示状态机拓扑图，右侧展示当前状态卡片、上行链路模式和动态动作按钮，强调当前所处阶段和下一步可执行动作；底部则显示运行日志和当前状态说明，用于记录整个模拟过程并补充业务解释。这样的布局从“系统级视角”逐步过渡到“状态级视角”和“操作级视角”，符合技术演示中由整体到局部、由结构到行为的阅读顺序。

在可视化设计上，项目采用了两类图形来分别表达两种不同的信息。第一类是“物理架构与数据流向图”，这部分使用 `ECharts` 的 `graph` 图实现，并通过 `Streamlit` 的 `components.html` 将自定义 HTML 注入页面。该图用于展示天线矩阵、毫米波基带、太赫兹/FPGA、信道探测、AD 参数、目标信息、DSP 核心、基带链路、云台控制箱、云台、CPU 和服务器之间的结构关系与信号流向。实现时没有采用随机布局或自动力导向布局，而是直接为节点设置固定坐标，将系统组织成上层信号源、中层处理模块、下层输出控制模块三层结构，使图形更符合工程系统的理解习惯，也更适合做汇报展示。

这张架构图的关键实现点在于“按状态驱动链路激活”。程序会根据当前状态计算不同数据流是否被激活，例如在搜索和回退阶段重点激活毫米波感知链路，在粗对准和跟踪阶段激活 DSP 到云台的控制链路，在捕获和跟踪阶段激活太赫兹链路，在跟踪阶段进一步激活基带链路到 CPU 和服务器的上报链路。随后系统再依据这些激活关系反推哪些节点需要高亮显示，哪些边需要增强显示，并给激活的边增加流动箭头动画效果。这样一来，用户在切换状态时不仅能看到状态名变化，还能直观看到系统内部哪些模块正在参与工作、信息沿着哪些路径传播，因此这一部分本质上属于“动态系统架构可视化”和“链路过程可视化”的结合。

第二类可视化是“状态机拓扑图”，这部分使用 `Graphviz` 生成有向图，并通过 `st.graphviz_chart()` 渲染到页面中。与顶部架构图不同，这一图不关心模块之间怎么连接，而是专门描述状态之间如何流转。图中清晰表示了正常推进路径、捕获失败后的回退路径、失锁后的退化路径以及毫米波恢复后的恢复路径。实现时采用从左到右的布局方式，使整个流程更接近常见工程流程图的阅读方向，同时对当前状态节点使用亮绿色高亮，对其他状态使用深灰色弱化显示，并使用不同颜色区分不同类型的边，其中蓝色表示正常前向推进，红色表示异常、超时或失锁，绿色表示恢复过程，橙色表示长时间无恢复后重新回到搜索状态。相比 ECharts，这种静态结构图更适合呈现状态机的拓扑关系，因此 Graphviz 在这里承担的是“逻辑结构表达”的职责。

选择 `ECharts` 和 `Graphviz` 两种技术并行，而不是统一使用一种图形库，是本项目的一个关键设计点。原因在于这两类图的表达诉求完全不同。物理架构图强调动态性、链路高亮、动画效果和交互缩放，适合使用 ECharts 这样的前端图形库来实现；状态机拓扑图强调结构稳定、边布局清晰、图形语义直接，适合使用 Graphviz 这类专门用于结构化图描述的工具来生成。两者组合后，既能从工程架构层面说明“系统现在在做什么”，也能从状态机逻辑层面说明“系统为什么会这样切换”，从而形成互补关系，提升整个演示系统的可解释性。

除了图形展示之外，系统还实现了状态监控、日志管理和调试能力，以保证整个模拟过程不仅“能看”，还“能操作、能追踪、能复盘”。页面右侧通过状态卡片展示当前状态编号和名称，并通过链路模式卡片显示当前上行使用毫米波还是太赫兹。动作按钮不是静态写死的，而是根据当前状态从 `STATE_TRANSITIONS` 中动态生成，只展示当前合法的转移操作，这样既能降低误操作，也能让页面行为严格遵守状态机设计。底部日志区采用控制台风格样式展示每一次状态变更的时间、起始状态、目标状态和触发事件，同时支持清空与导出，便于在演示结束后保存过程记录。

为了支持演示和测试，系统还额外提供了开发者调试面板，支持强制跳转到任意状态以及一键重置系统。这样做的价值在于，使用者不必每次都从 `S0` 顺序点击到目标状态，而可以直接进入某个场景进行展示或验证，例如快速进入 `S3` 观察捕获阶段的太赫兹链路高亮效果，或者直接跳转到 `S5` 演示回退和恢复逻辑。这一设计虽然简单，但大幅提升了系统在讲解和联调中的实用性，也让该工具更适合作为原型系统而不是一次性的静态页面。

总体而言，本项目采用 `Streamlit + ECharts + Graphviz` 的组合方案，在较低实现复杂度下完成了状态机逻辑表达、系统架构展示、链路动态演示和交互操作控制等多项需求。它本质上不是一个接入真实设备的控制系统，而是一个面向方案论证和原型验证的可视化模拟平台。当前方案已经能够清晰展示 DSP 瞄捕状态机在不同阶段下的逻辑演进和模块协同关系，后续如果需要，还可以进一步扩展自动播放、参数驱动切换、真实数据接入、日志持久化和离线资源本地化等能力，使其从演示型工具逐步演进为更贴近工程场景的半实物仿真界面。
